## 구현된 경로

기본 한국어 `/`, `/search`, `/seasons`, `/players`, `/players/{id}`, `/games/{id}`, `/records`, `/compare`, `/history`, `/data`. 영어는 각각 `/en` 아래 대응한다. 영어 HTML lang, 언어별 canonical/hreflang/설명, 고정 페이지 sitemap을 연결했다. 검색·비교 주소는 임의질의 색인을 방지한다.

기존 팬 화면은 `/fan`, 기존 뉴스·커뮤니티·칼럼·분석 상세 경로는 유지했다. 과거 홈 `?tab=community`와 `?tab=column`은 해당 목록으로 연결하고 뉴스/경기 탭은 fan으로 연결한다. 회원 데이터와 운영 DB는 변경하지 않았다. 기존 고정 선수 화면은 실제 기록 데이터 기반 선수 목록으로 교체했다.

검색은 검증된 로컬 데이터에 대해 선수/별칭·시즌·정규/PO·홈원정·상대·단일 지표 조건·정렬·합계·평균·경기수·두 선수 비교를 처리한다. 모호·미지원 질의는 거부하고 조건을 버려 답을 생성하지 않는다. 기록과 NULL·DNP·비활성·출전 미확인 상태를 분리한다. 기록표에는 양 팀 선수와 원자료 팀 합계·팀 전용 리바운드/턴오버를 구분해 표시한다. 한영 전환은 검색어·필터를 보존하고 한국어 표기가 미확보인 선수는 영문 원명을 사용한다.

## 저장과 추출

`data/records/dataset.json`이 없으면 정상적인 미확보 상태를 표시한다. 실제 기록은 현재 적재하지 않았다. 기존 캐시나 운영 DB를 기록 데이터로 자동 재사용하지 않는다. 모든 원천 ID는 내부 ID와 분리하고 승인된 로컬 데이터만 strict validation 뒤 최초 적재한다. 기존 파일을 덮어쓰지 않는다.

`npm run records:import -- /absolute/local.json --validate` 또는 `--import`. BALLDONTLIE 오프라인 자료는 `--format bdl`을 추가한다. 네트워크 조회·키 생성·구독·수집/백필을 실행하지 않는다. competition/neutral 검수값과 권리 evidence가 필요하다. 미확보 팀 합계·DNP·번역을 만들지 않는다. 문서와 합성 테스트 자료는 제품 DB로 적재하지 않았다.

독립 저장 스키마 `prisma/records.prisma`는 생성/적용 전 상태다. 기존 `prisma/schema.prisma`와 운영 DB는 그대로다. 실제 서비스는 JSON repository로 동작한다. 데이터 계약·CLI·검색 한계는 [records-data.md](records-data.md)에 있다.

## 검증과 범위

- 전체 TypeScript 검사 통과.
- 기록 검색/정합/오프라인 BDL 변환 합성 테스트 19개 통과.
- 독립 Prisma schema validate 통과(DB 연결 없음).
- 동일 UI 컴포넌트를 사용하는 브라우저 QA 미리보기에서 데스크톱/390px 모바일, 검색·언어전환·필터 복원·문서 가로넘침·런타임 오류를 확인했다.
- 추가 합성 자료 브라우저 QA에서 양팀·0점·DNP·NULL·출처·검색결과·선수로그·비교·미확보시즌 표시·모바일 containment도 통과했다. 실제 데이터를 제품 저장소에 적재하지 않았다.
- QA 미리보기는 Next navigation을 브라우저 URL로 치환한 별도 테스트 환경이다. 전체 Next 라우팅/SSR/메타데이터의 실행 검증을 대신하지 않는다.
- 전체 Next 빌드는 보관된 의존성의 `@next/swc-darwin-arm64@16.0.10` 바이너리 누락으로 실패했다. 패키지 복구 설치는 사용자 승인 대기다. 그 밖의 기존 경고/실행 문제는 실제 빌드 재개 뒤 확인한다.
